## 先让小实验可以解释

上一章你能训练和保存一个网络。这一章面对现实问题：同样一段代码，为什么今天不收敛，为什么评估时结果乱跳，为什么恢复训练后轨迹变了？

先修是第17章的评测分工、第20章的训练循环、Tensor和优化器。目标不是背更多参数选项，而是建立一条能逐步排除原因的检查路线。

## 1. “先过拟合极小数据”是一种诊断

想检查一辆车能否动，先在空地走几米。类似地，先取4到32条已核对的样本，关闭额外随机扰动，用足够有表达能力的小网络把训练误差压低，可以检查输入、标签、损失、梯度和参数更新是否连通。

这里的**过拟合小样本检查**是故意测试记忆能力，不是最终评测方法。若连少量一致样本都拟合不了，应依次看原始样本与标签、形状和类型、损失接收的是logit还是概率、梯度是否存在、参数是否改变，再看优化器与学习率。

但“小数据拟合成功”也不能证明标签正确。网络可能把错误标签一起背下来。更明确的故障例子是两个完全相同输入，却被标成相反类别，而模型输入里没有区分它们的额外信息。

若同一个输入两条记录标签分别为0、1，预测同一概率 $p$，这两条的平均交叉熵为：

$$
-\frac12[\ln p+\ln(1-p)].
$$

它在 $p=0.5$ 时最小，值为 $\ln2$。所以训练损失无法趋近0，不一定是网络太小，可能是标签与任务定义相互冲突。本章实验先制造这种错误，再根据已知XOR规则修正；真实任务不能为追求低损失随意改标签，应回查来源和标注规范。

## 2. 先看数据尺度，再谈更大模型

不同输入列若一列约0.01，另一列约10000，梯度尺度也可能很不均衡。第12、17章的训练集标准化能改善这种问题，但不保证解决所有优化困难。

还应区分样本级预处理和网络内部归一化。前者通常在训练前根据训练集统计固定规则；后者可能依赖网络中间激活和训练模式。先建立没有额外归一化层的最小基线，再逐项增加，便于解释改动效果。

批量大小影响每步统计、计算量、内存和梯度噪声。更小批量不一定训练更快，更多样本也不自动意味着更多独立信息。不要只记录epoch而不记录每轮数据量与更新次数。

## 3. Dropout：训练时随机让部分通道暂时休息

**Dropout**像练习时偶尔遮住部分提示，减少模型对某一条提示的依赖。准确地说，训练时以概率 $p$ 将某些激活置0，并对保留项按 $1/(1-p)$ 缩放。

对单个激活 $h$，令 $m$ 以概率 $1-p$ 取1、以概率 $p$ 取0，输出 $h'=mh/(1-p)$，因此 $\mathbb E[h']=h$。这里 $0\le p<1$；均值保持不代表每次输出一样。

PyTorch的普通 `nn.Dropout` 在评估模式下直接保留输入，不再随机置零。这就是为什么评估前要 `model.eval()`。仅用 `torch.no_grad()` 不会关闭Dropout，结果仍可能每次不同。[PyTorch Dropout](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Dropout.html)

Dropout不是必须加在每层的装饰；在极小数据排错时先关闭它，免得随机扰动掩盖问题。它也不能修复数据泄漏。

## 4. BatchNorm：用批内统计调整中间尺度

**批归一化**（Batch Normalization，BatchNorm）像先观察这一小组人的平均身高，再用“高出平均多少”描述每个人。准确地说，它在训练时用当前批次相关维度的均值与方差归一化激活，再用可学习参数恢复需要的尺度和偏移：

$$
\hat x=\frac{x-\mu_{batch}}{\sqrt{v_{batch}+\epsilon}},\qquad
z=\gamma\hat x+\beta.
$$

$\gamma,\beta$ 是可学习缩放和偏移，$\epsilon$ 是防除零的小常数。默认情况下PyTorch还维护运行均值与方差，评估时用这些积累统计而不是当前测试批的统计。运行统计属于缓冲状态，会进入state_dict。[PyTorch BatchNorm1d](https://docs.pytorch.org/docs/2.14/generated/torch.nn.BatchNorm1d.html)

因此 `train()` 和 `eval()` 不仅影响随机性，还会改变统计使用方式。小批量或训练与部署分布不同可能让统计不稳定。对只有一个样本且每通道没有额外观测维度的训练输入，BatchNorm1d甚至可能因无法计算所需统计而报错。

不要认为BatchNorm与第17章“只在训练集拟合预处理”矛盾：正常流程中它的运行统计也是训练时形成并在评估中固定。如果在测试数据上保持训练模式更新统计，就已改变评测协议。

## 5. CPU、GPU与精度：资源优化应晚于正确性

CPU适合本书这些小实验。GPU擅长大批量并行运算，但数据传输和启动也有成本，小网络不一定更快。**显存**是GPU使用的内存空间，训练时除权重，还要放梯度、优化器状态和中间激活。

**数值精度**描述浮点表示可以保留多少信息。float32通常每数4字节，float16和bfloat16通常2字节，但二者数值范围与有效精度不同。较低精度可能减少存储、加速特定硬件上的计算，也可能导致溢出、下溢或数值差异。

**混合精度**是不同运算按需要使用不同精度，常通过PyTorch `torch.autocast` 管理；某些低精度训练还需要梯度缩放以减少下溢。它应在已有float32正确基线后引入。[PyTorch AMP 文档](https://docs.pytorch.org/docs/2.14/amp.html)

本章没有运行GPU或混合精度实验，不把接口说明写成硬件性能实测。你当前需要掌握的是资源由哪些部分构成，以及性能优化后仍要核对损失和结果。

## 6. 梯度累积：把一大批拆成几小批再更新

如果一批放不进内存，可以分多次前向反向，把梯度累加后只更新一次。这里的**梯度累积**是跨小批量保留参数梯度，与第19章同一图中共享路径的梯度相加相关，但使用场景不同。

假设有效大批包含 $N$ 条，小批量第 $j$ 组有 $n_j$ 条、平均损失 $L_j$，正确整体目标为：

$$
L=\sum_j\frac{n_j}{N}L_j.
$$

因此每组反传前乘 $n_j/N$。当每组大小相同，才等价于“每组损失除以累积组数”。如果大小为3和2，不能简单各除以2，否则样本权重改变。

伪代码顺序是：累积开始时清零 → 每小批计算加权损失并反传 → 所有小批完成后更新一次。期间不要每批都 `optimizer.step()`，那已经是另一种训练轨迹。

对仅含逐样本运算、同一参数、相同总体损失的网络，梯度累积应与整批梯度近似一致。但BatchNorm依赖批内统计，Dropout有随机性，因此不能保证所有网络都严格等价。

## 7. 学习率调度与日志

**学习率调度器**像给训练安排不同阶段的步幅：前期快一点，后期细一点，或先从小步逐渐增加，后者常叫warmup（预热）。调度器不会替你判断数据是否正确。

本章恢复实验用 `StepLR`，每20次优化器更新把学习率乘0.5，按“更新步”计数，不按epoch。一般先 `optimizer.step()` 再调用本例的 `scheduler.step()`；不同调度器应核对其调用约定。恢复训练也要恢复调度器进度，不能让学习率重新从起点开始。

日志至少保存：配置、数据来源和划分、版本与设备、随机种子、步数、当前学习率、训练/验证损失、关键指标，以及出现错误时的一小批输入和预测。不要只保存一张漂亮截图。

## 8. 检查点应保存“继续下一步”需要的状态

**检查点**像游戏存档，应该保存继续运行所需的信息，不仅是画面上角色的位置。训练检查点通常包括模型state_dict、优化器state_dict、调度器state_dict、步数、随机数状态、采样顺序或数据迭代器进度，以及配置和数据版本。[PyTorch 检查点教程](https://docs.pytorch.org/tutorials/recipes/recipes/saving_and_loading_a_general_checkpoint.html)

本章实验固定数据，每步用 `torch.randint` 抽小批量，并使用Dropout，因此保存CPU随机状态足以覆盖这份程序的抽样与Dropout随机性。恢复时先重建并加载模型、优化器、调度器，最后恢复随机状态，避免对象初始化消耗随机数后改变轨迹。

我们对比“连续50步”和“20步存档，再恢复30步”。同环境下损失序列与参数应一致。真实多进程加载、GPU、NumPy或Python随机源的程序还需要记录其他状态；不同平台、版本或某些非确定性算子即使固定种子也不保证逐位相同。[PyTorch 可复现性说明](https://docs.pytorch.org/docs/2.14/notes/randomness.html)

## 9. 三个可运行的排错实验

```bash
python chapters/21-training-engineering/examples/debug_training.py
python chapters/21-training-engineering/examples/accumulation.py
python chapters/21-training-engineering/examples/resume_training.py
```

第一个展示冲突标签的误差下限和Dropout模式差别；第二个用大小3和2的小批量验证正确加权；第三个把模型、Adam、调度器和随机状态真正写入本章输出目录，重新读取并核对恢复轨迹。

对真实错误应保留“现象→假设→只改一个因素→结果”的记录。比如评估同一输入反复输出不同，先检查模型是否处于训练模式；不要首先怀疑数据文件损坏。发现冲突标签则回查数据，而不是盲目加大隐藏层。

## 过关标准

能把数据问题与优化问题区分开；能解释Dropout/BatchNorm模式差别；能正确按样本数累积梯度；能说明完整检查点多保存了什么；知道固定种子的可复现边界。下一章开始把一张图像变成网络能处理的数组。
