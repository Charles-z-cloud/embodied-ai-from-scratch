## 2.1 本章要完成的事

上一章画出了机器人观察、行动、再观察的回路。要让电脑执行其中任何一步，我们先要学会把指令保存成文件，并交给合适的软件执行。

本章只做一件小事：运行一个输出两句话的 Python 程序。你会知道文件放在哪里、命令在哪里输入、由哪个 Python 执行，以及怎样第二天重新打开它。前置是[第01章](../01-orientation/README.md)的“输入与输出”概念，不需要已有编程经验。

本机验证环境为 macOS、Apple 芯片、Python 3.12.10。这里用它验证基础示例，不要求你必须安装相同的小版本。Windows 和 Linux 的差异会单独标明；其界面步骤未在本机实际操作。

## 2.2 文件像本子，文件夹像书架

**文件（file）**是一份有名称、可以保存的数据。照片、文章和程序都可以是文件。**文件夹，也叫目录（directory）**，用来组织文件和其他文件夹。

`hello.py` 是一个文件名。末尾的 `.py` 称为**扩展名**，常用来表示这是 Python 源代码。源代码就是人写下来的程序文字。`.md` 表示本教材采用的 Markdown 文档，`.txt` 通常表示普通文本。

扩展名是一种命名约定，不会自动改变文件内容。把一张照片改名为 `hello.py`，并不能把它变成程序。还要留意编辑器是否偷偷保存成 `hello.py.txt`：如果系统隐藏扩展名，你看到的名称可能不完整。查看文件属性或打开“显示扩展名”即可核对。

接下来会创建如下结构。先把它当作整理方式，稍后亲手创建：

```text
ai-study/
├── hello.py       ← 你编写的程序
└── .venv/         ← 这份学习项目的 Python 环境
```

树状图中的线条只是画图符号，不是文件名的一部分。以点开头的 `.venv` 在一些系统里默认隐藏，可以在终端查看，也可以开启文件管理器的隐藏文件显示。

## 2.3 路径：告诉电脑“去哪里找”

你要去学校，可以说完整地址，也可以说“从这里向右走”。找文件时也有这两种描述方式。

**路径（path）**是文件或目录的位置描述。**绝对路径**从某个文件系统的起点写起；**相对路径**从当前约定的位置写起。

| 写法 | 含义 |
| --- | --- |
| `/Users/mei/ai-study/hello.py` | macOS 上的绝对路径示例，用户名 mei 仅是举例 |
| `C:\Users\Mei\ai-study\hello.py` | Windows 上的绝对路径示例 |
| `hello.py` | 当前目录里的这个文件 |
| `examples/hello.py` | 当前目录中 examples 文件夹里的这个文件 |
| `.` | 当前目录 |
| `..` | 上一级目录 |

macOS、Linux 主要用 `/` 分隔路径。Windows 常见 `\` 与盘符。本章 Windows 命令采用 PowerShell。文件名大小写规则会受系统和文件系统影响，因此教材始终保持大小写一致。

“当前目录”究竟是谁的当前目录？接下来我们使用终端执行命令，它有自己的**工作目录（working directory）**。终端根据这个位置解释相对路径。编辑器当前显示某个文件，并不会自动让终端进入那个文件所在的文件夹。

## 2.4 终端、命令与参数

**终端（terminal）**像一个可以通过文字交办事情的窗口。你输入命令，电脑执行，然后显示结果。负责理解这些命令的程序称为 **shell**。macOS 常见 zsh，Linux 常见 bash，Windows 可以使用 PowerShell。本书不要求你现在熟悉它们全部功能。

在 Mac 上可搜索并打开“终端”。输入下面的命令，每行输入完成后按回车：

```bash
pwd
ls
```

`pwd` 显示工作目录的路径，`ls` 列出其中可见的文件。你看到的输出取决于自己的电脑，不必与他人相同。Windows PowerShell 可以使用 `Get-Location` 和 `Get-ChildItem` 完成相应查看。

一条命令通常由“做什么”和“对什么做”构成。例如：

```bash
mkdir ai-study
cd ai-study
```

`mkdir` 创建目录，后面的 `ai-study` 是目录名；`cd` 改变工作目录，后面是目的地。命令后用来补充信息的部分称为**参数（argument）**。空格通常用于分隔命令和参数，因此路径有空格时需要加引号，例如 `cd "my study"`。

请在你愿意存放练习的目录中创建 `ai-study`，不要覆盖已有内容。若它已存在，直接进入。运行一次 `pwd` 确认位置。创建文件夹并不等于已经进入了它，`cd` 才改变工作目录。

Windows PowerShell 的对应操作是：

```powershell
New-Item -ItemType Directory ai-study
Set-Location ai-study
Get-Location
```

`-ItemType Directory` 表示创建的项目类型是目录。一个终端窗口中的目录切换通常不会改变另一个终端窗口的工作目录。

## 2.5 谁来读懂 Python 程序

写菜谱的本子不会自己做饭。同样，保存了一段程序，还需要软件读懂并执行它。**Python 解释器（interpreter）**就是执行 Python 程序的软件。

**编辑器（editor）**负责让你写和修改文件；解释器负责执行。二者可以整合在同一个软件中，但作用不同。你可以使用现有的代码编辑器，或使用 Python 安装环境附带的 IDLE。用普通文本编辑器时，确认保存为纯文本，而不是带字体样式的富文本文件。

先检查电脑是否已经有 Python。在 macOS 或 Linux 终端执行：

```bash
python3 --version
```

`--version` 请求显示版本，不是让你运行某个程序文件。本机输出为 `Python 3.12.10`。三个数字用于区分发行版本；这里只记录它们，不需要背。

Windows 可以先试：

```powershell
py --version
```

若安装方式提供的是 `python` 命令，则执行 `python --version`。需要把实际能找到的命令用于下一步。若显示“找不到命令”，这表示终端没找到相应程序，不能据此断言你的 `hello.py` 写错了。

尚未安装时，从 Python 官方提供的当前平台安装说明进入： [macOS](https://docs.python.org/3/using/mac.html)、[Windows](https://docs.python.org/3/using/windows.html)。安装完后重新打开终端，再检查版本。Linux 的安装方式取决于发行版；先检查已有 `python3`，缺少时使用该发行版的软件管理说明。有些发行版把 venv 支持放在独立的软件包中。

这一步选一个受支持、适合你电脑的 Python 3 即可。后面外部机器人项目有自己的版本要求，会单独建立环境，不把所有项目塞进这一套环境。

## 2.6 为什么给项目准备独立的环境

设想做手工时，每个作品有自己的工具盒。一个作品换了工具，不必把另一个作品的工具也换掉。**虚拟环境（virtual environment）**也有类似用途：为项目准备相对独立的 Python 解释器入口和已安装的软件包集合。

**包（package）**在这里可以先理解为别人整理好的可复用程序，例如以后用来处理数组的工具。一个项目需要哪些包及版本，称为它的**依赖（dependencies）**。不同项目可能需要不同版本，虚拟环境能减少它们相互干扰。它不是另一台电脑，也不是完全隔离的操作系统。

在 `ai-study` 工作目录内，macOS/Linux 执行：

```bash
python3 -m venv .venv
```

逐项读这条命令：`python3` 指定解释器；`-m` 表示运行 Python 提供的一个工具模块；`venv` 是创建环境的工具名称；`.venv` 是环境目录名。现在只需了解这些命令参数，如何编写自己的模块会在第05章讲清楚。

Windows 如果使用 `py`，则执行：

```powershell
py -m venv .venv
```

创建完成通常不会打印很多内容。环境里使用的 Python 版本来自创建它的解释器，不会因为目录叫 `.venv` 就自动选中某个版本。这些行为可对照 [Python venv 官方说明](https://docs.python.org/3/library/venv.html)。

### 不激活也可以使用

最明确的方式是直接写出环境解释器的位置。macOS/Linux：

```bash
.venv/bin/python --version
```

Windows PowerShell：

```powershell
.\.venv\Scripts\python.exe --version
```

路径中的 `bin` 或 `Scripts` 是环境存放可执行程序的位置。本章先采用这条直接路径，你就能清楚知道用的是谁。

### 激活只是让输入更方便

macOS/Linux 可以执行：

```bash
source .venv/bin/activate
command -v python
python --version
```

第一行让当前 shell 使用环境的设置；第二行显示当前 `python` 命令找到的程序路径。随后可以写较短的 `python`。执行 `deactivate` 恢复先前的命令查找设置。关闭终端后，下次仍要重新进入目录并激活，或者继续使用解释器的直接路径。

Windows PowerShell 对应的激活脚本是 `.\.venv\Scripts\Activate.ps1`。如果系统阻止运行该脚本，本章可以直接使用 `.\.venv\Scripts\python.exe`，仍然能够运行全部练习，不需要为了跟上教材改变系统策略。

## 2.7 写下并运行第一个程序

用编辑器在 `ai-study` 中创建 `hello.py`，只写下面两行并保存：

```python
print("你好，具身智能！")
print("我的第一个程序正在运行。")
```

`print` 表示把括号里的内容输出到屏幕。括号说明输出内容放在哪里，引号表示其中是一段文字。引号本身不会随文字打印。括号和引号使用英文半角符号；其中的中文可以正常保留。

先不用考虑其他语法。这两行按从上到下的顺序执行。把文件保存之后，在其所在工作目录运行：

```bash
.venv/bin/python hello.py
```

Windows 使用：

```powershell
.\.venv\Scripts\python.exe hello.py
```

预期输出为：

```text
你好，具身智能！
我的第一个程序正在运行。
```

执行过程是：终端找到解释器 → 解释器读取 `hello.py` → 执行两条输出指令 → 终端显示结果。修改第一句、保存、重新运行，就会看到新的文字。

本教材也提供了同样的[示例文件](examples/hello.py)。从本章目录运行可用 `python3 examples/hello.py`；这条命令用于检查示例，选择独立环境时请用你实际环境的解释器路径。

### 区分终端命令与 Python 交互窗口

如果只输入 `python3` 而没有文件名，可能进入显示 `>>>` 的 Python 交互窗口。这里可以输入 `print("你好")`，但不能把 `cd ai-study` 当作 Python 代码输入。

需要回到终端时，在 `>>>` 后输入 `exit()`。本书代码框不包含需要复制的 `$`、`%` 或 `>>>` 提示符。也不要把预期输出写进源文件。

## 2.8 包的安装命令先认识到哪里

本章示例只需要 Python 本身。以后安装包时会用到 **pip**，它是 Python 常见的包安装工具。先查看独立环境里是否可用：

```bash
.venv/bin/python -m pip --version
```

它通常会显示 pip 版本、所在路径及 Python 版本。我们写“解释器路径 + `-m pip`”，是为了明确对哪个环境操作。只写 `pip` 时，可能找到另一套环境中的程序。

以后需要安装时才会使用 `python -m pip install 包名` 这种格式；`包名` 是解释位置的中文占位，不能原样执行。一个已安装版本清单也不等于项目全部资源记录，数据和模型文件还要另外说明。

## 2.9 从报错中找出下一步

| 现象 | 先检查什么 | 为什么 |
| --- | --- | --- |
| 找不到 python3 或 py | 解释器是否安装，终端能否找到它 | 程序还没有开始执行 |
| 找不到 hello.py | 工作目录和文件真实名称 | 相对路径可能指向了别处 |
| 找不到 `.venv/bin/python` | 环境是否创建、是否位于正确目录 | 解释器路径本身也是路径 |
| 修改后输出没变 | 文件是否保存，运行的是不是同名副本 | 编辑内容不一定已经写入被执行的文件 |
| SyntaxError | 引号、括号、字符是否完整 | 源码不符合 Python 的书写规则 |
| venv 创建失败 | 最后几行报错及平台的 venv 支持 | 不能假定“目录出现了”就代表创建成功 |

每次排错先回答三个问题：我现在在哪个目录？我要运行哪个文件？我用的是哪个解释器？这能解决很多刚开始写程序时的困惑。

## 2.10 小结与过关

文件保存代码，编辑器负责修改，解释器负责运行，终端负责接收执行命令。相对路径依赖工作目录，虚拟环境帮助项目管理自己的依赖。

过关时请独立做到：创建目录与程序；从终端运行；把输出改成自己的文字；关闭终端后重新找到项目并运行；记录 Python 版本与解释器路径。还应能解释为什么“终端找不到命令”和“Python代码写错”是不同问题。

执行记录见[检查记录](validation.md)。下一章将在这个程序上加入数字、变量和简单计算。平台细节的参考是 [Python 使用说明](https://docs.python.org/3/using/index.html)及[环境与包教程](https://docs.python.org/3/tutorial/venv.html)，核验日期2026-10-24；它们用于查阅，不是本章的额外先修课。
