## 把全部部件放到同一个实验里

现在你已经学过词元化、嵌入、下一个词元目标、注意力、位置编码和Transformer block。本章把它们连接成一个可以从随机参数训练并生成短文本的模型。

**GPT**是Generative Pre-trained Transformer的缩写，通常指以因果Transformer进行自回归文本建模的架构路线。本章使用相同的基本思想，称为“小型GPT式模型”；它只有小语料和少量参数，没有经过大规模通用预训练，不是缩小参数就自动拥有大模型能力。

## 1. 先明确语料和评价范围

语料全部由本章自编模板组合生成，避免不清楚来源或许可的大规模下载。颜色为红/蓝/绿，物体为方块/圆球，方向为左/右/前/后，动作为移到/推到，前缀为空/请/现在，共144条互不相同的短指令，例如“请把红色方块移到左边。”。

用种子7按整条文本打乱，100条训练、22条验证、22条测试。先拆分原始句子，再构造滑动窗口；不允许同一句话切出的相邻窗口跨集合。三份集合文字不同，但共享模板和大量词元组合，所以测试只能衡量这套人工语法里的新句子，不能代表自然中文或新任务泛化。

词表仅从训练文本建立，另外加入PAD、UNK、BOS、EOS。验证和测试中的字符如果不在词表，按UNK处理并报告。本实验在生成后显式检查评测字符都已覆盖，不偷偷利用测试文本扩词表。

## 2. 窗口怎样构造，标签怎样计数

**滑动窗口**像拿一个最多能看到C个词元的小框，在一句话上逐步移动。完整序列为BOS、正文、EOS。对每一个需要预测的词元，取它之前最多C个词元作为输入，目标就是这个词元。

本章采用容易审计的实现：每个窗口只训练最后一个有效输入位置的预测。因此每条句子的每个目标词元（包括EOS）在一个完整训练样本表里恰好出现一次，不会因为重叠窗口重复统计目标。

短前缀右侧补PAD到C，记录有效长度 $\ell$，只取输出位置 $\ell-1$ 的logit。由于PAD全在有效前缀之后，因果注意力不能从有效位置访问它们；未选取的PAD查询不参与损失。这个实现不支持直接改为左填充，也不代表所有网络都可以省略PAD键mask。

位置编码从窗口开头0重新编号。生成时也只保留最后C个词元并从0编号，保持训练与使用约定一致。更长上下文并非只改一个常数就能保证外推可靠。

## 3. 模型与训练预算

结构为：词元嵌入 → 固定正弦位置编码 → 两个Pre-LN decoder block → LayerNorm → 线性词表头。模型维度32，4个注意力头，每头8维，FFN维度128，无Dropout，使用CPU float32。

本章分别训练上下文C=4和C=16两种配置。两者可学习结构与参数量相同；位置表长度不同但不是可学习参数。随机初始化种子7、窗口抽样种子11，Adam学习率0.003，每次32个窗口，固定400次更新，每50步用完整验证窗口计算平均交叉熵并保留最佳权重。

这里不把400步称为400轮：每一步只是从训练窗口表随机抽32条，不保证恰好遍历一轮。训练目标仍是第25章的平均下一个词元交叉熵：

$$
L=-\frac1B\sum_{i=1}^{B}\ln P_\theta(y_i\mid\text{窗口前缀}_i).
$$

PAD和BOS不作为输出候选，将其logit屏蔽；EOS和UNK属于允许输出集合。生成与评测使用同一规则。

## 4. 与bigram公平比较

比较对象是第25章讲过的bigram算法，但重新在**本章相同100条训练文本、相同词表**上计数，平滑系数0.1。不能拿第25章另一份语料的PPL直接比较。

两种Transformer和bigram都在相同22条最终测试句子的同一批目标字符上计算NLL与PPL，EOS计入、BOS/PAD不计作目标。bigram只看前一个词元，Transformer看不超过C个。

这是一组固定预算下的教学对照，不是各方法充分调参后的排行榜。较长上下文在这套局部模板任务上不一定更好；它可能带来额外能力，也可能更难优化或更容易拟合训练组合。必须报告实际结果，不能预先编造“上下文越长分数越好”。

## 5. 训练代码的关键连接点

模型在 `forward(ids)` 返回(B,C,V)的logit。用每条样本自己的有效末位置取出(B,V)：

```python
all_logits = model(inputs)
last_logits = all_logits[torch.arange(len(inputs)), lengths - 1]
loss = F.cross_entropy(last_logits, targets)
```

这与第16章普通分类器的损失形式相同，只是输入表示来自一个因果Transformer。标签类型long，参数通过反向传播同时更新嵌入、注意力、FFN和输出层。

`model_parts.py` 保留第27章同一份模块实现，使本章代码可直接运行；它不是第三方模型源码。训练主文件中模型、数据构造、评测、采样各有单独函数，便于定位形状或掩码问题。

## 6. 生成、停止与保存

从BOS出发，取当前前缀最后一个位置的概率，贪心或按温度抽样，再把新词元加入前缀。遇到EOS停止，最多生成30个词元；出现UNK时保留可见标记，不静默删掉。

每个配置打印固定种子的采样结果和一条贪心结果，不人工挑选最好看的句子。流畅并不等于理解：语料只包含模板指令，模型没有任何视觉输入，也没有与机器人环境交互。

模型存档保存最佳验证权重、配置与词表，再重新构造模型加载，核对同一批输入logit一致。它是本章用于推理复现的存档，不包含完整训练中断恢复的全部状态；第21章讲过恢复Adam轨迹还需要什么。

## 7. 运行与记录

```bash
python chapters/28-tiny-language-model/examples/train_language.py
```

运行后，本章 `examples/output/` 包含原始文本划分、词表、两种上下文配置的权重、验证轨迹、测试指标及生成文本。用本地CPU完成，不调用付费接口，也不下载外部模型或大数据集。

应同时检查训练目标和输出样本：若NLL接近允许词表大小的对数且长期不下降，先核对标签位移、有效位置和优化器；若损失很低但输出一直重复，检查EOS计数、生成时输入更新及是否丢失上下文；若验证远差于训练，考虑数据与模型容量，而不是继续盯测试集调参。

具体数值见[实际检查记录](validation.md)。结果将包含失败或不理想的现象；教材的目标是能解释实验，不是把每个小模型都描述成成功的语言理解系统。

## 8. 经典项目：怎样读nanoGPT

[karpathy/nanoGPT](https://github.com/karpathy/nanoGPT) 是经典的紧凑GPT实现，适合在完成本章后对照阅读。核验日期2026-10-24：作者README已在2025年11月标记此仓库陈旧并弃用，将它保留作历史参考。因此本书把它用作源码阅读材料，不作为默认安装和长期维护的训练框架。

先看 [model.py](https://github.com/karpathy/nanoGPT/blob/master/model.py) 中的注意力、MLP、Block与GPT类，对照本书已学部件；再看训练文件怎样取批、累积梯度、记录验证和保存。遇到分布式训练、编译、权重绑定等附加机制时，先标注为选学，不用一次理解所有优化细节。

**权重绑定**像让输入查词表和输出打分共用同一份词元向量表；在合适维度约定下可让输出投影使用嵌入矩阵的转置。它能减少参数，但不是本章实现的必需部件。本章输入嵌入与输出头独立。

没有运行nanoGPT完整训练，也没有复现其论文级模型；本书实际结果只来自自编小模型。若以后运行外部项目，应固定commit、核对依赖与资源，再在独立环境尝试最小配置。

## 过关标准

能从原始句子一路解释到ID、窗口、logit、损失和生成；能证明训练与评测没有共享原句；能说清NLL/PPL的分母；能加载模型复现输出；能区分模板续写能力与视觉、行动和真实知识。下一章把预训练、微调和指令评测的关系讲清楚。
