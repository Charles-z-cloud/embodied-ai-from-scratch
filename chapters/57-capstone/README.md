## 学完以后，你应该能做什么

## 1. 先写任务合同

“任务合同”像游戏开始前约定胜负规则，准确地说是对可用观测、动作、状态变化、终止条件和评价协议的明确规定。我们的桌面有红、蓝两个目标和一个移动点。指令只有“到红目标”与“到蓝目标”，实现为0和1两个ID，不接受任意自然语言。

| 项目 | 本项目规定 |
|---|---|
| 图像 | 16×16 RGB，颜色高斯光斑，无遮挡 |
| 自身信息 | 当前二维位置 |
| 共同感知 | 手写颜色重心，提取两个目标坐标 |
| 动作 | 二维速度，每轴在[-0.5,0.5]米/秒 |
| 步长 | 0.1秒，理想位置积分 |
| 成功 | 到原指令目标的距离小于0.09米 |
| 失败 | 100步内未成功 |
| 评测 | 新场景种子400—419，已见组合与保留组合各20例 |

原始图像经同一重心函数转成四个数，再加自身位置形成六维特征。评测器知道真实目标，策略只能得到感知特征和指令。用真实目标判断是否成功是合理的；把这个隐藏坐标偷偷塞进策略输入则改变了信息条件。

“保留组合”沿用第52章：指令红与红目标第一象限、指令蓝与蓝目标第三象限，未进入该章训练。这只对第52—53章的指令策略构成特定组合外推；第41章状态BC和第47章动力学的训练分布不同，不能把这个组称为所有模型共有的未见分布。

## 2. 四条路线，连接到同一个动作接口

**手写控制器**：按指令选择感知目标，按误差算速度。结构先验最强、无需训练，是本任务很有竞争力的基线。

**状态行为克隆（BC）**：先用手写规则按指令选目标，再把自身位置和感知目标喂给第41章策略。它的神经网络本身不读语言，所以应称“规则选目标+状态BC”，不能说它学会了指令理解。

**指令条件连续策略**：复用第53章连续回归头及第52章冻结特征网络，读取六维特征和指令ID，直接给出速度。这是小型VLA数据流的演示，视觉前端仍是人工设计。

**学习动力学+规划**：按指令选感知目标，用第47章动力学预测候选动作的后果，再用第49章CEM寻找较低成本的动作。本章固定规划时域3、每轮128条候选、3轮迭代、保留16个精英。只执行第一步，再根据新观测规划。

这四条路线获得相同外部信息，但编码先验、训练数据、参数量和计算预算并不相同。因此这是一场系统比较，不能单凭成功率证明某一种学习目标具有普遍优势。

## 3. 先冻结协议，再看结果

本章不重新训练任何模型，不根据这批结果修改超参数。选择新种子400—419，避免把第53章报告的同一组场景再次当成新证据。每种方法报告成功率、平均步数和每次策略调用的平均墙钟时间。失败轨迹按100步计入平均值，不能只统计成功案例的速度。

世界模型规划需要更多计算，这个成本必须和成功率一起看。墙钟时间在本机CPU测得，没有独立预热或严格性能隔离，且不含共同图像生成与重心计算；它是本次运行记录，不是跨硬件性能基准。

成功率估计仍是 $\widehat p=k/N$。例如20次全部成功，第54章Wilson 95%区间的下界约0.839，说明样本量小。请不要把20/20写成“已经证明可靠”。

## 4. 消融要对准想问的问题

项目额外运行以下对照，每次仅在对应系统内改变指定因素：

- 指令连续策略把四个目标坐标置零，检查视觉信息缺失的影响；自身位置保留。
- 指令连续策略把红蓝指令交换，成功标准仍使用原指令，检查模型是否利用指令。
- 规划器把学习动力学换成已知真实积分关系，检查模型误差在当前规划中的影响。
- 规划器把预测改成“位置始终不变”，故意删除动作对未来的作用，检查动作条件预测的重要性。

最后一种模型仍能被规划器调用，但它让所有动作的目标距离项相同，只剩动作幅度惩罚；因此规划倾向小动作，很难完成到达任务。这是一个可解释的故障基线，不是训练出来的强无模型竞争者。

**历史信息单独考察。** 当前二维任务给出了足够的即时状态，增加记忆并非必须。不能为了讲历史而声称此任务天然需要RNN。第38章闪烁线索和第48章遮挡序列才有隐藏信息；该章已比较当前帧、简单历史和GRU。本项目把它们列为独立的“部分可观测性实验”，不与当前任务成功率混成一张排名表。若要把遮挡加入毕业项目，必须先定义缺失标志与记忆接口，再训练并独立评测；本版未实现这个扩展。

## 5. 从零准备与一键运行范围

这里的“一键”指权重已准备后的统一评测，不代表首次使用不需训练。先激活全书环境，依次执行：

```bash
python chapters/41-imitation-learning/examples/bc.py
python chapters/47-learned-dynamics/examples/dynamics.py
python chapters/52-vla-discrete-actions/examples/train_vla.py
python chapters/53-vla-continuous-actions/examples/continuous.py
python chapters/57-capstone/examples/capstone.py
```

如果前四章已经完成且对应权重存在，只运行最后一条。模型加载和各章使用的训练数据生成器都随教材提供；不下载真实机器人数据、不购买GPU、不连接硬件。具体Python依赖见根目录[环境说明](../../environment.md)。

脚本检查四个必需检查点是否存在，缺少时给出生成命令；从第49章导入规划器类不要求先运行该章评测。脚本输出完整JSON到忽略目录，并把可公开阅读的摘要写到[项目结果](results.md)。所有成功与失败轨迹都保留，不只挑最好的一条。

## 6. 结果该怎么读

先比较同一任务组内四种完整系统；再比较同一系统的消融。查看黑图是否只是碰巧走到目标附近，交换指令是否走向另一个目标，世界模型故障是否使动作接近零。行为解释需要轨迹支持，单个成功率不能说明全部原因。

当前模型并不是专为毕业项目重新公平训练的，它们复用各章权重，是为了教你集成与分析。若你的研究问题是“哪一种架构在相同预算下更好”，需要另建统一训练数据、超参数搜索和多训练种子协议。本项目不能替代那项实验。

## 7. 交付自己的毕业作业

提交内容应包括任务合同、模块图、环境版本、运行命令、训练与测试划分、全部系统结果、至少一个失败案例、至少两个有明确假设的消融，以及结论限制。用[验收清单](acceptance.md)自查。

推荐只做一个改动，例如把速度上限降一半，**先写预测**，然后重新评测并解释结果；或者改变目标外观，观察手写视觉前端在哪里失效。不要同时换任务、网络和奖励后，把结果变化归给其中一项。

完成本项目不意味着已经能部署通用机器人；它说明你能把感知、语言条件、决策、预测和闭环评测连接起来。最后一章将用这个能力重新整理四个最初困惑你的概念。
