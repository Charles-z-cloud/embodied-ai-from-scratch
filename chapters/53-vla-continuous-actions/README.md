## 动作不必先变成文字式token

第52章将动作量化成9类。**连续动作头**像直接输出油门刻度而不是选择固定档位，是从条件表示产生连续动作值或其分布的网络模块。输出连续并不代表自动精确，也不意味着一定使用扩散；普通回归、概率分布、扩散和流匹配都可以产生连续动作。

**动作专家（action expert）**通常指专门处理动作生成的子网络，不一定是人类专家或第41章的示范教师。视觉语言骨干可以负责条件理解，动作模块负责在这些条件下产生动作序列；连接方式可能是拼接、跨注意力或共享Transformer计算。

## 1. 先画清条件如何进入

令c=F(I,l,s)为视觉、语言和机器人状态的融合表示。回归头给 $\hat a=g_\theta(c)$；流匹配动作头给 $v_\theta(A_\tau,\tau,c)$，其中Aτ是正在生成的动作块。

训练使用示范A，与标准高斯Z构造 $A_\tau=(1-\tau)Z+\tau A$，目标为：

$$L=\mathbb E\|v_\theta(A_\tau,\tau,c)-(A-Z)\|^2.$$

生成从Z开始，沿τ=0到1积分，然后恢复动作单位并执行。这里输出是连续速度场，不是文字词表logit；交叉熵、回归MSE、流匹配速度MSE分别监督不同量，数值不可直接比较谁更好。

动作块H×d_a可展平再输入MLP，也可保留时间结构交给Transformer。第46章已经生成两步动作；本章为隔离动作表示，主实验取H=1，即每次生成一个二维速度并重新观测，不把它称为已验证长动作块。

## 2. 冻结和联合训练的取舍

冻结F只训练动作头，可以控制实验变量并减少更新成本；如果F丢失动作所需的细粒度位置，头再复杂也难补救。联合微调允许改表征，但可能破坏已有语义或过拟合小数据。LoRA也是一种适配选择，不能默认更少参数就保持所有原能力。

本章继承第52章训练好的指令嵌入和64维融合网络并冻结，固定质心视觉编码器不变。用相同示范访问状态，标签改为量化前的教师连续速度；因此离散与连续标签表达不同，不能把差异全归于网络结构。连续头均从随机初始化训练。

## 3. 归一化和采样器也是模型的一部分

动作范围[-0.5,0.5]米/秒，流匹配训练先除0.5映射到[-1,1]。生成完成后裁到[-1,1]再乘0.5，恢复单位。不能忘乘回去，也不能把归一化动作直接当位置增量。

每次生成使用新噪声，固定评测种子可复现抽样。更多采样步一般增加计算，但没有保证单调提高任务成功率；数值误差、模型偏差及闭环随机性都会影响结果。采样得到一个动作后还需限幅、按频率执行并接收反馈。

## 4. 同任务实测

```bash
python chapters/52-vla-discrete-actions/examples/train_vla.py
python chapters/53-vla-continuous-actions/examples/continuous.py
```

连续回归头：64→64→2，tanh输出限幅。流匹配头：输入64维条件、二维噪声动作和τ，共67维，两层64宽SiLU后输出二维速度场。两者Adam0.003、1000次更新、批128、种子7；每100步各自用验证目标选模。流匹配验证使用固定噪声与τ，减少选模抖动。

相同40个已见组合、40个保留组合起点，比较第52章离散策略、连续回归、4步流匹配、16步流匹配。回合种子固定，生成噪声种子为回合seed+1000。报告成功率、平均环境步数，以及每次策略调用平均耗时。时间包括条件计算和采样，不包括图像质心预处理，不能冒称完整系统端到端延迟。

[检查记录](validation.md)保留全部结果，包括更慢却未改善的配置。此任务的教师动作基本单峰，生成策略未必有优势；第46章已经说明多峰任务为何可能需要分布表达。

## 5. 代表架构怎么读

[π₀论文](https://arxiv.org/abs/2410.24164)是视觉语言表征与流匹配动作生成结合的代表；[openpi作者仓库](https://github.com/Physical-Intelligence/openpi)包含不同模型路线，阅读时区分流动作模型与自回归动作模型，不把同仓库所有模型当作一种结构。

核验日期2026-10-24，仓库对完整运行列有独立平台与GPU要求；本书未安装或下载大模型。先完成本章CPU实验，再按某个具体版本核对视觉输入、状态字段、动作统计、动作头和推理频率。不要把真实机器人模型的7维动作原样用于本书2维环境。

过关要求：区分语义特征与动作输出；写清谁冻结、谁更新；跟踪归一化到真实单位；用任务成功与延迟比较头部；认识到“连续”“生成式”“大模型”是不同属性，不能互相替代。
