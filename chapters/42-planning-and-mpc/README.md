## 已经会控制，为何还要规划

第41章策略看到观测就直接给动作。**规划**像先在草稿纸上试几条路线，再选下一步，是利用模型比较候选行动后果的过程。这里模型是第37章已知更新方程，不是神经网络；先理解已知模型，才能在第47—49章判断学习模型的误差带来什么影响。

## 1. 先把目标写成代价

**代价（cost）**是越小越好的评价数，奖励通常越大越好。**规划时域H**是本次向未来考虑的步数。给当前状态s₀和候选动作序列 $A=(a_0,\ldots,a_{H-1})$，用模型 $s_{k+1}=f(s_k,a_k)$ 推演，然后计算：

$$J(A)=\sum_{k=0}^{H-1}\ell(s_{k+1},a_k)+\ell_f(s_H).$$

ℓ是每步代价，ℓ_f是末端代价。它帮助短时域考虑终点是否接近目标，但不能保证看不见的远期风险全部解决。**约束**是候选必须满足的条件，例如动作限幅、关节范围、碰撞距离；仅在代价里惩罚违规不一定保证满足硬约束。

本章沿用位置p和目标g，取 $\ell=\|p-g\|^2+0.01\|a\|^2$、$\ell_f=5\|p-g\|^2$。两项物理单位不同，系数隐含相应尺度权重；它是本实验的优化指标，不是第37章原奖励的简单逐项取负。最终仍用环境成功率评测。

**rollout**像把一条计划在脑中播放，是从当前状态依次应用动作得到预测轨迹的计算。规划时rollout可能不与真实环境交互，必须与真实执行日志分开。

## 2. 随机射击：先试很多方案

**随机射击（random shooting）**像随机画许多条路线并选最便宜的一条，是直接采样多个完整动作序列、分别推演并选最优的方法。H=10、每步2维动作，每条候选有20个数；384条候选形成(384,10,2)数组。

优点是无需对模型求导，容易并行；缺点是维数变高后随机碰到好方案很难。它并不是用随机动作直接控制：随机发生在内部候选搜索，真正执行的是评估后选出的动作。

## 3. 交叉熵方法逐渐缩小搜索范围

**交叉熵方法（CEM）**像先试很多路线，留下成绩最好的小组，再围着它们继续试，是通过精英候选更新采样分布的优化方法。与第16章分类交叉熵同名有关联，但此处不是在训练分类器。

本章以每个时间动作维独立的高斯作为采样分布，初始均值0、标准差0.3；每轮采128条，按J选16条最小代价的精英，用其均值和标准差更新分布，标准差不低于0.05；共3轮。样本最终裁到动作范围，故执行样本的实际分布不是未裁剪高斯。

返回全部搜索轮中代价最低的候选，不把均值自动当成最佳方案。均值可能不满足非凸任务的几何要求。本任务没有障碍，但未来不能因此忽略碰撞。

## 4. MPC为什么只做第一步

**模型预测控制（MPC）**像走一步就重新看地图规划，是不断重复“观测→短时域优化→执行首个动作”的控制方式。计算出的十步计划只执行第一步，再读取新状态。

如果一次执行整段计划，中途扰动和模型误差会累积；滚动重算有机会修正，但也需要足够计算速度和有效观测。MPC不等于自动有稳定性保证，其性能取决于模型、目标、约束、时域和求解质量。

**热启动**像把上次计划剩下的部分作为这次草稿，是复用上一轮优化结果帮助本轮搜索。本章CEM把旧最优序列左移一步，末尾补0，作为下次均值；每次标准差重新设0.3，保留探索空间。随机射击基线不热启动，因此虽然模型评估次数一样，搜索策略也不止相差更新公式；报告应说明。

## 5. 同一任务上的比较

```bash
python chapters/41-imitation-learning/examples/bc.py
python chapters/42-planning-and-mpc/examples/mpc.py
```

先训练前章BC，再比较手写反馈、BC、随机射击MPC、CEM-MPC。使用种子200—219同一20个起点，正常与前章同样的第三次决策前位置跳变各评测一遍。H=10，随机射击384条、CEM三轮各128条，因此每次决策均评估3840个模型步，不包括直接策略的运算。

记录成功率、平均环境步数、每次策略调用的本机平均及95百分位耗时。**95百分位**表示95%的观测耗时不超过这个值，不是最坏情况上界。第37章周期100ms，若计算超过这个周期，真实部署需另行处理；本章同步仿真不会自动把计算时间加到物理时间。

候选推演使用与环境相同的边界裁剪，但为方便代价计算，即使预测中进入成功区域也继续推满H步。这是明确的固定时域代价设计；它不同于环境成功后终止的回报，不应说完全精确优化了原MDP奖励。

[检查记录](validation.md)保留结果。深入阅读可看[MIT轨迹优化课程](https://underactuated.mit.edu/trajopt.html)，先抓住动力学约束、阶段代价、终端代价和滚动执行，再扩展更复杂求解器。

过关要求：知道每个候选包含多少动作；区分预测轨迹与执行轨迹；解释热启动；把规划质量与计算耗时一起比较；明确“用模型规划”并不要求模型一定从数据学习。下一阶段先学习生成模型，为多解动作和潜在世界模型做准备。
